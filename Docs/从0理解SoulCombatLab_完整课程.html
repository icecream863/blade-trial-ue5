00 / 从能看到的现象开始

短按一次左键，究竟发生了什么？

本章学会：把整个项目理解为几个接力完成的动作，而不是一堆类名。

先用游戏里的现象理解代码

你短按左键，角色挥出第一刀；攻击中再按一下，第二刀会在合适的动画时刻接上；受到打断后，再按会重新起手。课程就沿这三件事展开，再把伤害、防御、敌人和关卡流程接起来。

按键：玩家想做什么→技能：现在能做吗→招式表：应该是哪一招→战斗执行：播放并结算

只需先认识这六个词

词在这个项目里是什么
Controller解释按键的人；控制当前玩家角色。
Character / Pawn世界里的玩家身体；拥有模型、移动和各种组件。
Component装在角色身上的专职功能，例如连招或锁定。

自测：第一刀到底由哪个地方决定动画？

Moveset 起手索引指向的 Steps 节点提供 Montage，Combat 选中节点后，通过自己的私有 PlayAttackMontage 播放它。Controller 只判定轻/重请求。

展开：源码细节与额外证据

先记住一句话：Controller 识别左键短按或长按，技能检查能否攻击，连招组件选第几刀，战斗组件播放动画。

  1. 按下并很快松开左键。Controller 把它解释为“轻击”，再请求角色攻击。
  2. 技能检查。如果角色被击晕、体力不足等，攻击不会继续。
  3. 选招式。现在还没出招，连招组件从招式表选轻击起手（当前资产是 Attack01_1）。
  4. 播放动画。战斗组件播放这刀的 Montage；刀刃命中窗口到来时，才开始检测打中了谁。
接第二刀时，多出一个“等待”：第一刀还在播放时再次短按，输入可以先存起来。只有第一刀动画走到“允许接招”的窗口，第二刀才会真正播放。按键被接收，不等于第二刀已经打出。

01 / 从入口开始

游戏到底从哪里开始？Controller 在哪？

本章学会：明白打开工程后，角色、控制器与玩法流程怎样接上。

从进入游戏到控制角色

  1. 配置选择 L_CombatLab 和 BP_SCLPlayerGameMode。GameMode 给出玩家、Controller 和 HUD 的类。
  2. ASCLGameMode::StartPlay 在 Demo 模式下创建运行时区域；标题界面等待开始操作。
  3. Enter → Controller 的 Primary → Demo 的 PrimaryAction → StartStage(Spawn)。
  4. Demo 按 GameMode 配置生成玩家，通过 Controller->Possess(Player) 占有它，占有回调负责安装本地输入映射。
  5. Controller 的 SetupInputComponent 调用 BindPlayerActions 绑定自身动作；回调通过 GetPawn 操作当前角色。

Possess 可以理解为“让这个控制器开始控制这个身体”。Controller 可以保留，失败重试时 Pawn 可以换成新的实例。

在哪里配置

/Game/SoulCombatLab/Blueprints/GameModes/BP_SCLPlayerGameMode 选择玩家 BP_SCLPlayerSamurai 与控制器 BP_SCLPlayerController。模型、动画、装备配置属于玩家蓝图；输入资产与长按阈值属于控制器蓝图。

观察任务：PIE 从标题进入游戏，在 Outliner 选实际玩家，确认 Actor 类、Controller、Mesh 和 Anim Class；死亡重试后再次检查。

自测：重生后输入资产与绑定需要重新创建吗？

不需要。动作资产和绑定属于保留的 Controller。失去 Pawn 时卸载映射并清长按状态；占有新 Pawn 后重新安装相同映射对象，回调读取新的 GetPawn。

展开：源码细节与额外证据

Controller 的 C++ 基类是 ASCLDemoPlayerController；Content 中的 BP_SCLPlayerController 继承它，并由玩家 GameMode 选择。

  1. DefaultEngine.ini 把默认地图设为 L_CombatLab，GameMode 指向 BP_SCLPlayerGameMode。
  2. 它的 C++ 基类 ASCLGameMode 给出默认 Pawn、HUD 和原生 Controller；BP_SCLPlayerGameMode 将 Player Controller Class 配置为 BP_SCLPlayerController。GameMode 负责“生成哪个类”；Controller 持有动作与映射、在自己的输入组件上统一绑定动作，解释攻击短按、长按并处理菜单热键。
  3. 标题页按 Enter 时，USCLDemoSubsystem::PrimaryAction 调用 StartStage(Spawn)。该函数清理旧对象、生成玩家、让 Controller 占有玩家，然后配置生命、体力和敌人。
当前生成路径：BP_SCLPlayerGameMode 的 PlayerCharacterClass 指向 BP_SCLPlayerSamurai_C；StartStage 重生时读取 GameMode 对当前 Controller 的默认 Pawn 类，再生成和占有该类。2026-09-30 的 RuntimeFlow 回归通过；断言同时核对实际 Controller 为 BP_SCLPlayerController_C、与 GameMode 配置一致，以及重生 Pawn 类与 GameMode 选择一致。若更换 GameMode 配置，应重新检查首次进入与重试时的实际 Pawn 类。
在 UE 中找它：Content → SoulCombatLab → Blueprints → Player → BP_SCLPlayerController。再打开 GameModes → BP_SCLPlayerGameMode 的 Class Defaults，检查 Player Controller Class。它继承 C++ 按键处理；重击阈值在该 Controller 蓝图的 Class Defaults 中配置。

完整走一遍：短按第一刀，然后缓存第二刀

  1. Controller 松开左键，按时长判断 Light；Character 向 GAS 请求轻击。
  2. Ability 验证资格后调用 Combat::RequestAttack(Light)。
  3. Combat 向 PlayerCombo::SelectAttack 取选招结果。只缓存时返回 Buffered；选中节点时进入 StartPlayerAttackStep。
  4. StartPlayerAttackStep 检查 Montage、当前体力和 Effect Spec，通过后调用同一类的 PlayAttackMontage。这个私有函数保存 Playback 实例 ID，并向 ActionMovement 申请 Attack 朝向与根运动。
  5. 成功起播后，Combat 按 Step 扣一次体力，确认 Combo 当前节点，添加攻击状态；动画失败则取消本次并返回失败。
  6. 攻击中再按，Combo 保存一笔输入。ComboWindow 通知由 Combat::IsActiveAttackNotify 直接核对 Playback.InstanceId，再由 Combo 交出缓存节点。
  7. 缓存节点仍进入同一个 StartPlayerAttackStep。WeaponTrace 通知驱动武器采样，Combat 经目标 TakeDamage 结算生命与韧性。
  8. Montage 委托直接回到 Combat。FinishAttackPlayback 使实例失效、释放 Attack 移动申请并停止轨迹；FinishAttackIfReady 确认动画和范围查询都结束后清理招式。

取消也在同一个类里连续阅读：CancelActiveAttack → CancelAttackPlayback（先让实例 ID 失效，再 Stop）→ CancelAreaImpact（递增代次）→ EndWeaponTrace → 清理配置与 Combo。旧动画回调、旧范围遍历会因身份失效退出。

为什么这些成员分别放在 Controller 和 Character

UPROPERTY 只是向 UE 登记属性，不决定它归哪个类。此工程现在采用统一玩家控制方案：DefaultMappingContext、MouseLookMappingContext、RuntimeCombatMappingContext 与所有 InputAction 都由 Controller 持有，定义动作、创建运行映射、绑定、安装与卸载也在同一个类。Character 不再通过 friend 暴露私有输入字段。

DeveloperComponent 留在角色：组件的 Owner 是这个角色，实验要读取其位置、GAS 和战斗组件，计时器与实验实现归组件自身。CachedMovementInput 也留在角色：它是当前身体的移动意图，供移动和躲闪技能共享；Controller 传入数值，角色结束输入或失去控制时清掉它。

其他项目可采用不同 Pawn 提供不同输入方案的设计；这里选择 Controller 持有完整输入配置，是为了让同一个玩家的控制与重生流程更集中。并非 UE 禁止 Character 持有输入资产。

03 / 一次鼠标输入的路线

轻击与重击不是两颗键

本章学会：跟踪一次短按和一次长按，读懂请求函数。

先分清“动作定义”和“安装映射”

InputAction 定义输入的含义和数值类型；MappingContext 把具体键连接到动作。Controller 构造默认动作与基础资产引用，PostInitializeComponents 用本实例的动作创建瞬态战斗映射，SetupInputComponent 再绑定回调。映射中的 Action 与 BindAction 的 Action 必须是同一个对象；名字相同不够。

RuntimeCombatMappingContext 使用 Transient + VisibleInstanceOnly：不保存成蓝图配置，只在运行实例中查看。实际拥有本地角色时安装映射；失去控制或退出世界时卸载。OnPossess 处理服务端/单机，AcknowledgePossession 处理本地客户端确认；本轮单机测试不等于网络验证。

按下与松开是两次事件

左键 Started 调用 HandleAttackPressed：清旧状态，启动长按计时。达到阈值时发重击；很快松开时才确定短按轻击。当前默认阈值为 0.25 秒。

void ASCLDemoPlayerController::HandleAttackReleased()
{

锁定和格挡如何同时改变移动

修改参数的位置没有变：LockedWalkSpeed 在 Targeting，BlockingSpeedMultiplier 在 Block Ability。参数的应用和恢复统一归 ActionMovement。

例如基础步速 500，锁定上限 180，格挡倍率 0.55，最终步速 = min(500, 180) × 0.55 = 99。先格挡后锁定也得到相同结果。格挡中丢失目标，LockOn 撤销上限，仍保留格挡倍率，速度变为 275；再松开格挡恢复 500。反过来先松开格挡，则恢复锁定步速 180。

不再由每个动作保存旧 MaxWalkSpeed 再互相恢复。每个动作只撤销自己的申请。普通速度配置变更通过 SetBaseWalkSpeed，有限制时也能重算；不要绕过组件写 MaxWalkSpeed。

朝向用名称集合：Attack 解除后如果 LockOn 仍存在，就仍不朝移动方向旋转。根运动使用优先级：武器表现 10，攻击、弹反、处决 100；同级后申请者优先。旧动作结束仅撤销自己，不用旧 RootMotionMode 快照覆盖新动作。

void USCLActionMovementComponent::ApplyWalkSpeed()
{
	const ACharacter* Character = Cast<ACharacter>(GetOwner());
	if (!Character || !bSpeedBaselineSaved) return;
	float Speed = BaseWalkSpeed;
	for (const auto& Limit : SpeedLimits) Speed = FMath::Min(Speed, Limit.Value);
	for (const auto& Multiplier : SpeedMultipliers) Speed *= Multiplier.Value;
	Character->GetCharacterMovement()->MaxWalkSpeed = Speed;
	if (SpeedLimits.IsEmpty() && SpeedMultipliers.IsEmpty()) bSpeedBaselineSaved = false;
}

伤害链按顺序追

  1. WeaponTrace Notify Begin → Combat::BeginWeaponTrace → 武器 HitTrace::BeginTrace，记录首帧刀根/刀尖间的采样点。

  4. TraceHit → Combat::HandleTraceHit → ApplyAttackDamage → ApplyPointDamage → 目标 TakeDamage。
  5. 受击端处理无敌、弹反和格挡，剩余伤害交给 ASC/Effect 修改生命；当前路径只有实际生命伤害大于零才追加韧性伤害。

感知：发现玩家→黑板：保存目标与距离→行为树：追击/攻击/换位→GAS 与 Combat：执行

黑板是行为树共享的上下文。Service 周期更新战斗信息；Task 做具体动作。攻击 Task 请求 GAS，监听攻击状态变化，攻击结束后安排恢复或换位；EQS 查询候选位置，再由换位 Task 移动。

Boss 多了一层选招评分

Utility 策略根据距离、阶段和近期攻击历史给候选评分，避免立即重复招式；没有有效覆盖的招式可以返回 None。选择结果转换为一次运行时攻击配置，再交给 Combat 播放。二阶段扩展可选招式与参数。

玩家通过 Moveset 节点选招；敌人使用共享 AttackData 的 Montage Section。二者在 Combat 内分开选择，武器命中和伤害路径仍能共用。

修改任务：改普通敌人的移动速度、生命等先找 Archetype；改 Boss 在某距离偏好的招式先找 Utility；改某招动画/伤害执行再找攻击配置。先确认选招日志，再确认实际动画。

自测：Boss 评分选出一个招式，是否说明它已经命中玩家？

选招只是决定候选。还要准备参数、技能检查、播放动画、进入命中窗口并通过目标受击处理，才可能造成伤害。

敌人自动连段与范围招

Combat 消费一次 Pending 攻击配置；Combat 起播后，MontageComboState::Start 按 FirstStep 与 StepCount 连接 Section，末段后继设为 None。Buffer 只安排后继，不代表后继已经开始，因此当前、缓存、排队三个索引分别保存。

范围招关闭武器轨迹，Combat::ScheduleAreaImpact 设置自己的单次计时器。ApplyAreaImpact 查询 Pawn，过滤自身、已死亡、无 ASC 和敌人同类目标；同 Actor 去重后，ApplyAreaDamage 直接复用 ApplyAttackDamage。伤害回调可能同步取消攻击，AreaImpact.Generation 改变就退出剩余遍历，旧查询不会清掉新招。

动画先结束而查询未完成时保留本次伤害配置；查询先完成而动画未结束时保留动画取消入口。两者都结束才清理。这两个“结束”不能当成同一个事件。

自测：100 点体力，轻击起手后在窗口接一次重击，忽略体力再生，剩多少？

100 - 6 - 12 = 82。轻击后缓存重输入时仍是 94；只有重击实际接出后才是 82。

值得保留

玩家连招图数据化，轻/重分支直观；输入缓存与 Montage 窗口分开；CombatComponent 共用命中执行；旧 Montage 回调有实例 ID 防护；重生使用 GameMode 配置的玩家类。

仍有阅读成本

重击 Ability 继承轻击 Ability；轻/重类型由技能明确提供并逐层传参；Character 执行角色动作；Controller 持有全部输入配置、管理映射并绑定和解释按键；调试场景已移到独立 DeveloperComponent。蓝图兼容入口 StartLightAttack 暂时保留。

若继续优化，可先把玩家攻击输入类型显式传到共享攻击请求，再评估统一窗口推进和体力结算的责任。每一步都要用实际 PIE 检查刀位、根运动、特效和取消恢复；自动化测试通过不能代替手感检查。

推荐表述：“当前玩家使用 DataAsset 定义 10 节点轻重连招图；Controller 把左键短按/长按解释为轻击或重击，Character 发起攻击请求，GAS 检查状态与体力，ComboComponent 管一格输入缓存和下一节点，Montage NotifyState 开放接招及命中窗口，CombatComponent 切换 Montage 并执行武器命中。Demo 重生使用 GameMode 配置的玩家类；共享攻击入口为 RequestAttack。”
